Step 1: A Basic Dashboard Script¶

This step shows the smallest complete ctest -S script that configures, builds, and tests a project, and submits the results to CDash.

The Example Project¶

Most steps build the project in the Project directory, which defines two tests:

passes

A test that exits successfully.

fails

A test that exits with a non-zero exit code.

Project/CMakeLists.txt¶
cmake_minimum_required(VERSION 3.20)
project(DashboardExample CXX)

include(CTest)

add_executable(passes passes.cxx)
add_test(NAME passes COMMAND passes)

add_executable(fails fails.cxx)
add_test(NAME fails COMMAND fails)

# Optionally add a target that fails to compile, to show how build errors
# are reported on the dashboard.
option(DASHBOARD_EXAMPLE_BUILD_ERROR "Add a target that fails to compile" OFF)
if(DASHBOARD_EXAMPLE_BUILD_ERROR)
  add_executable(error error.cxx)
endif()

The project's CTestConfig.cmake file tells CTest where to submit results. These examples submit to the sandbox project on my.cdash.org:

Project/CTestConfig.cmake¶
set(CTEST_NIGHTLY_START_TIME "00:00:00 UTC")
set(CTEST_SUBMIT_URL "https://my.cdash.org/submit.php?project=sandbox")

The Script¶

Step1/submit.cmake¶
# Set the name of this build to distinguish it from other builds on CDash.
set(CTEST_BUILD_NAME "Step1: introduction")

# Look up the name of this host and use it as the site name.
# Alternatively, set CTEST_SITE directly.
site_name(CTEST_SITE)

# Tell CTest where the top-level CMakeLists.txt file is, and what directory
# to use to build the project.
set(CTEST_SOURCE_DIRECTORY "${CTEST_SCRIPT_DIRECTORY}/../Project")
set(CTEST_BINARY_DIRECTORY "${CTEST_SCRIPT_DIRECTORY}/build")

# Specify the native build system to generate.
set(CTEST_CMAKE_GENERATOR "Unix Makefiles")

# Attach this script as a note to the build on CDash.
set(CTEST_NOTES_FILES "${CMAKE_CURRENT_LIST_FILE}")

# Perform a "version-only update" with Git.  This reports the current
# commit and any locally modified files to CDash without changing the
# source tree.
set(CTEST_UPDATE_COMMAND "git")
set(CTEST_UPDATE_VERSION_ONLY 1)

# Start from an empty build tree rather than building incrementally.
ctest_empty_binary_directory("${CTEST_BINARY_DIRECTORY}")

# Run the dashboard steps to configure, build, and test the project,
# and submit the results to CDash.
ctest_start(Experimental)
ctest_update()
ctest_configure()
ctest_build()
ctest_test()
ctest_submit()

The script runs these steps:

ctest_start()

Begin a new dashboard submission.

ctest_update()

Record the current Git commit and any modified files.

ctest_configure()

Run CMake to configure the project.

ctest_build()

Build the project.

ctest_test()

Run the tests.

ctest_submit()

Submit the results to CDash.

Key Concepts¶

CTEST_BUILD_NAME

The name of the build on the dashboard. Use it to distinguish several builds of the same project, such as by platform, compiler, or configuration.

CTEST_NOTES_FILES

Attaches files to the build as notes. Attaching the script itself makes it easy to see what produced a given result.

CTEST_UPDATE_VERSION_ONLY

Records the current Git commit without updating the source tree. This is useful when a CI system has already checked out the source.

ctest_empty_binary_directory()

Removes the build tree before the dashboard starts, so that each run is a clean build.

Running the Script¶

ctest -S Step1/submit.cmake -V

The ctest -V option prints the output of each step.
